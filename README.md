# Med Queue — Інтелектуальна система управління чергами у медичних закладах

Вебзастосунок корпоративного рівня для автоматизації процесів попереднього запису, моніторингу живої черги та оптимізації графіку роботи медичного персоналу в реальному часі.

Система вирішує проблему нерівномірного навантаження на лікарів, мінімізує час очікування пацієнтів за допомогою алгоритмів пріоритезації та запобігає простоям кабінетів через автоматизовану обробку неявок (no-show).

---

##  Ключовий функціонал

- **Попередній запис та планування:** Програмний розрахунок вільних слотів на основі робочого календаря лікаря.
- **Динамічна жива черга:** Розрахунок ваги пріоритету на основі часу запису, фактичного часу очікування в клініці та типу прийому.
- **Функціонал Check-in:** Процедура фіксації прибуття пацієнта з миттєвим переміщенням його статусу у черзі.
- **Режими доступу:** 
  - *Панель Реєстратора (Адмін):* управління штатом лікарів, моніторинг усіх черг клініки.
  - *Кабінет Лікаря:* перегляд власного розкладу та живої черги, керування статусами прийому.
  - *Кабінет Пацієнта:* запис на прийом, перегляд історії та статусу власного візиту.

##  Швидкий старт (Docker)

### 1. Клонування та конфігурація

```bash
# Перейдіть у робочу папку проекту
cd med-queue

# Створіть файл локальних змінних з прикладу
cp .env.example .env
```

> **Вимога:** Перед першим запуском перевірте `.env` та переконайтеся, що порти не зайняті іншими сервісами на хост-системі.

### 2. Збирання та запуск

```bash
# Автоматичне збирання образів та запуск у фоновому режимі
docker compose up --build -d
```

Ця команда:
1. Ініціює збирання локальних контейнерів бекенду та фронтенду.
2. Завантажує легку версію СКБД `postgres:16-alpine`.
3. Створює ізольовану віртуальну мережу `med_network`.
4. Проводить автоматичну синхронізацію схем таблиць бази даних при старті FastAPI.

### 3. Перевірка доступу

| Компонент | Протокол | Локальна адреса URL |
|:---|:---|:---|
| **Клієнтський інтерфейс** | HTTP | [http://localhost:3000](http://localhost:3000) |
| **REST API Бекенд** | HTTP | [http://localhost:8000](http://localhost:8000) |
| **Документація API (Swagger)** | Docs | [http://localhost:8000/docs](http://localhost:8000/docs) |
| **База даних PostgreSQL** | TCP | `localhost:5432` (User: postgres) |

### Генерація даних (seed.py)

Для демонстрації можливостей черги передбачено скрипт-сідер, що генерує збалансований набір синтетичних даних на поточну добу.

**Команда виконання:**
```bash
docker compose exec backend python seed.py
```

**Логіка роботи:**
* Перевіряє цілісність бази даних.
* Створює 3 профілі лікарів різних напрямків.
* Генерує акаунти 5 пацієнтів.
* **Оновлює** розклад на поточний день, створюючи свіжі візити для миттєвого тестування статусів черги.

##  Технологічний стек проєкту

- **BackendCore:** FastAPI, Uvicorn, Python 3.12.
- **Database & ORM:** PostgreSQL 16, SQLAlchemy 2.0, Asyncpg (асинхронний драйвер).
- **Data Validation:** Pydantic v2 (типізація, валідація JSON-структур).
- **Frontend:** Next.js (App Router), React 18, Tailwind CSS, Lucide Icons.
- **Infrastructure:** Docker Desktop, Docker Compose, Bridge Isolation Networking.

##  Безпека та продакшн рекомендації

Перед деплоєм рішення у продуктивне середовище переконайтеся у виконанні наступних пунктів:
1. Згенерувати стійкий `SECRET_KEY` для підпису токенів.
2. В `.env` змінити `ENVIRONMENT=production`.
3. Заборонити прямий проброс порту `5432` в `docker-compose.yml` (видалити мапування портів для `db`).
4. Налаштувати CORS профілі у FastAPI лише на довірені домени клієнта.
